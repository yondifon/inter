# Dogfood report — 2026-07-29

## Scope

Claims tested:

1. Inter picks a suitable model for task depth and preference.
2. Inter uses the correct CLI and arguments for each profile.
3. Inter exposes useful events while a task is still running.

Environment: Bun 1.3.14, Codex 0.145.0, Claude Code 2.1.217, OpenCode 1.18.4.

## Results

### Model selection — NOT VERIFIED

`bun test` passes the five routing cases. Mechanical work selects a cheap model,
context work requires quality 4, and architecture work requires quality 5.

This proves deterministic behavior, not correct real-world selection. Routing
uses prompt regexes plus model-name heuristics. It does not use profile
capabilities, context-window needs, observed success, latency, or provider
reliability. Most live catalog entries have no price metadata, so cost routing
falls back to names. The connected Inter MCP also still requires `profile`,
while current source and README describe automatic routing. Deployed behavior
therefore differs from the current source.

### CLI selection — INCONCLUSIVE

Adapter tests confirm expected argv for Claude, Codex, OpenCode, custom commands,
model overrides, and Claude hooks. Model discovery returned live catalogs for
all enabled profiles.

No test launches each installed CLI and verifies accepted arguments plus parsed
output. Discovery also catches every error and silently returns the configured
model. A changed or broken CLI command can therefore look healthy.

A live Codex smoke test was attempted with read-only scope. The delegation gate
rejected sending local `package.json` data to an external model account. This is
a good safety default, but the product gives no built-in safe fixture or consent
flow for dogfooding.

### Running events — NOT VERIFIED

Inter stores JSON stdout lines and Claude hook events during execution. Event
normalization tests pass.

`wait` wakes only for `needs_input`, `completed`, or `failed`. New progress
events never notify waiters. The HTTP event endpoint returns a snapshot; it
offers no SSE stream, cursor, long poll, heartbeat, or stalled-task signal.
Malformed and oversized event lines are dropped, and hook events do not wake
waiters. Inter captures progress but does not let a caller listen to it live.

## Evidence

```text
bun test
30 pass
0 fail
51 expect() calls

bun run typecheck
exit 0
```

Installed profiles and model catalogs were read through the connected Inter MCP.
The connected tool schema exposed `delegate(profile, model?, prompt, cwd)` and
did not expose the current source's automatic `delegate(prompt, cwd, ...)` or
`route` tool.

### Live Codex smoke run

After explicit user approval, the same delegation passed the host safety gate:

```text
Profile: codex
Model: gpt-5.6-luna
Scope: read package.json only; no edits
Created: 2026-07-29T15:49:15.548Z
Completed: 2026-07-29T15:50:22.921Z
Duration: 67.373s
Result: Package manager: Bun / Test command: bun test
```

The first 30-second `wait` timed out with state `running`, empty output, and an
unchanged `updatedAt`. The next wait returned the completed result. No progress,
heartbeat, startup phase, or last-event time was visible through MCP. The
documented local event endpoint at `127.0.0.1:7331` was unreachable from the
calling session even though the connected MCP transport worked.

This run verifies Codex execution and final-text parsing. It does not verify
automatic routing because the deployed MCP schema required an explicit profile.
For this two-line read, 67 seconds also makes CLI startup/agent latency a major
routing input; model speed alone does not predict user-perceived speed.

## Improvements

1. Add a checked-in, non-sensitive smoke fixture and run one task per enabled
   provider. Record CLI version, argv contract, first-event latency, event kinds,
   terminal state, duration, and parsed final text.
2. Make discovery failures visible in `models` and health state. Keep fallback,
   but label it degraded with the exact failed command and exit status.
3. Add event cursors to `wait`; wake on new events as well as terminal state.
   Return `afterCursor`, recent progress, last-event time, and a stalled flag.
4. Add SSE or cursor-based long polling to `/api/tasks/:id/events`.
5. Version the MCP contract and show source/deployed version mismatch in health.
6. Replace name-only routing evidence with a task matrix and outcome log. Start
   with mechanical, codebase review, implementation, debugging, architecture,
   and long-context tasks across cost, speed, balanced, and quality preferences.
7. Use profile capabilities and catalog metadata as hard filters. Treat missing
   cost, tool-call support, context size, or discovery health as explicit
   uncertainty in the route explanation.
